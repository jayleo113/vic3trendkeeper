# Trend Keeper · 维多利亚3 历史曲线修复（v4）

> **定位：让游戏里原有的图表直接变完整。** 原版图表和图表类 mod 画的都是引擎里的趋势数据（`GetGDPTrend`、`GetPopulationTrend` 等，用 `GetTrendPlotPointsNormalized` 画出整条曲线，不截取时间段）。Trend Keeper 在数据源头修复，不覆盖任何界面文件，所以和图表 mod 天然兼容。按你已安装的 mod 逐个核对：
>
> | mod | 读取的数据 | 效果 |
> |---|---|---|
> | GDP Plotline Plus | GDP、声望趋势 | 跟着变完整 |
> | GORA UI+ | GDP、人口、生活水平、价格、建筑等趋势 | 跟着变完整（价格、建筑趋势原版就不存档，见第三节） |
> | GDP Chart、Global Stats、GDP Ownership Display、Dense Market Details | 只显示当前数值，不画趋势 | 不受影响 |
>
> 之前做过的独立图表面板 mod（Full History Charts）已经从启动器撤下，源文件保留在仓库的 `full_history_charts/` 目录。
>
> **启动方式**：
> - **一次性准备**：运行 `python tools/trend_keeper.py shortcut`，会在桌面放一个"Trend Keeper"快捷方式（折线图图标，打开时没有黑窗口）。
> - **每次玩之前**：双击桌面图标（或 `tools/启动 Trend Keeper.bat`）。助手窗口会等游戏启动，自动附加并打补丁，不用任何操作。先开助手、再开游戏最稳，补丁会在读档前打上；游戏已经开着再启动助手也可以，但扩容类补丁只对之后读档生成的曲线生效。
> - **托盘**：点窗口右上角关闭时，助手默认缩到托盘继续运行（设置里可关）。左键托盘图标显示/隐藏窗口，右键弹出菜单：状态、打开主窗口、默认修复开关、限制自主投资开关、热点采样、退出。设置里还有"启动时只显示托盘图标"。
> - **开机自启（可选，默认不装）**：运行 `python -I -B tools/trend_keeper.py install-autostart`，在 Windows 启动文件夹放一个快捷方式，开机后助手无窗口运行。撤销：`关闭开机自启.bat` 或 `uninstall-autostart`。

- 已测试版本：Victoria 3 **1.14.5**（`victoria3.exe` 97,774,200 字节）。
- 所有补丁位置都通过特征码在磁盘 exe 中定位，写入前逐字节核对原始内容。版本不符时助手自动进入只读模式，不做任何修改。
- 运行 `python trend_keeper.py selftest` 可以离线检查当前 exe 是否适配，不需要开游戏。

| 国家人口、阶层人口 | 只有 ID 能被 7 整除的国家才记录 | **所有国家，100 年** | 是 |
| 国家激进/忠诚人口 | 10 年 | **100 年** | 是 |
| 利益集团影响力 | 10 年 | **100 年** | 是 |
| 利益集团激进/忠诚 | 1 年 | **10 年**（折中，见第三节） | 是 |
| 公司曲线 | 100 年 | 不变，不再清空 | 是 |
| 预算各项收支 | 1 年 | **100 年** | 否：原版设计，读档后从读档日起记录 |

| 单个 pop、政治运动、战争、市场价格 | 1 年，或只记玩家国家 | 不变（见第三节） | 否 |

- **观察者模式**：上表中写入存档的曲线，只要**从开局起助手就一直开着**（勾选"游戏启动后自动应用"），就能看到开局以来的完整时间线。预算曲线能看到从最近一次读档开始的完整时间线。
- **已经在进行的存档**：先用 `tools/恢复存档历史.bat` 处理一遍（见第五节）。处理后可以扩容、去掉伪平线、补回被清空的历史。补丁开启之前从来没有被记录过的数据，任何办法都找不回来。

## 二、根因（逆向结论）

1. **离开国家时曲线被清空。**
   - 国家不再被跟踪时，游戏调用 `SetCountryTrendStatus(国家, 0)`（`0x1407FAC70`），继而调用 `ClearCountryTrends`（`0x1407FB1E0`）。
   - 后者在做完簿记之后，清空该国的 GDP、声望、生活水平，以及州、建筑、公司、市场、利益集团的曲线。
   - 触发场景：你切到别的国家；该国改 tag 或成立新国家；观察者模式下换了观察对象。
2. **人口曲线有 ID%7 的 bug。**
   - 每周执行的 `RecalcCountryPopStatistics` 只在 `IsTrendUpdateDay(国家)`（`0x140C7B9C0`）为真时才推送人口曲线。
   - 对 AI 国家，这个判断是"国家 ID 除以 7 的余数等于当天天数除以 7 的余数"。但任务本身每 7 天才跑一次，天数那一项永远不变，所以只有 ID 能被 7 整除的国家会被记录。
3. **观察者模式下其它国家的州、建筑曲线停更。**
   - 每周的 `CTrendManager::Update` 第一个循环遍历全图所有州，对每个州先查它所属国家的跟踪状态（`游戏状态+0xE0` 数组里的值，1 或 2 才算被跟踪），不是就**直接跳过**州和建筑曲线的写入（判断在 `0x1414943B5`，跳过的跳转在 `0x1414943BF`）。
   - 所以曲线会停在"这个国家最后一次被跟踪"那天，之后游戏时间再往前走也不再有新点。`keep_history` 只保证不清空，不会让它继续记录。
   - 国家级曲线（GDP 等）走的是另一个循环（`0x140C7B940`，AI 国家按节奏更新），不受这个问题影响。
4. **容量是写死的。**
   - 曲线在构造时由 `Init(曲线, 采样间隔, 时长)`（`0x1414522E0`）决定容量。时长以 6 小时为单位：100 年是 `0x23A50`，10 年是 `0x3908`，1 年是 `0x5B4`。
   - 写满之后按环形缓冲区覆盖最老的数据。曲线在第一次推送数据时，会按容量一次性分配内存。

## 三、补丁与取舍

| 补丁 | 默认 | 改动 | 代价 |
|---|---|---|---|
| `keep_history` | 开 | 在清空函数中只跳过"清空曲线"那一段：通过代码洞 `0x1400014E0` 执行原函数唯一的非趋势写入后，直接跳到函数尾声 | CPU 为 0 |
| `fix_pop_stats` | 开 | `0x140C7736A` 处的 `call IsTrendUpdateDay` 改为 `mov al,1`。只改这一个调用点；同一函数的另一个调用者是预算缓存，会影响游戏逻辑，**没有碰** | 实测测不出 CPU 差异；存档每游戏年约 +0.2 MB |
| `track_all_states` | 开 | `0x1414943BF` 处 2 字节的 `jne` 改成两个 `nop`，州循环对所有国家都执行。所有州的曲线结构在创建时就已初始化，写入时通道按需创建，不会访问未初始化的数据 | 每周多写入全部州的曲线，容量仍是原版的 1 年；内存增长未长期测，开启后 1 分钟内在 ±0.3 GB 的波动内。补停更期间引擎会用最后一个值补平线（最多 1 年） |
| `extend_saved` | 开 | 9 处 `Init` 或 `Reserve` 的时长立即数：国家激进/忠诚（构造时、变为被跟踪时、变为不被跟踪时）以及利益集团影响力改为 100 年，利益集团激进/忠诚改为 10 年 | 内存约 +48 MB；存档每游戏年约 +0.5 MB |
| `extend_budget` | 开 | 预算构造函数中 32 处时长立即数，1 年改为 100 年 | 内存约 +135 MB（立即分配）；不影响存档 |
| `cap_investment` | 关 | 限制自主投资每周落地次数（见 `docs/`）：把原落地次数 n 限制为 min(n, max(最小值, 预算÷潜在建筑数))。代码放在助手在游戏进程里申请的一块可执行内存里，预算和统计在线可调 | **会改变模拟结果**，联机必须所有人同样开启；默认预算 1500、最小 4 是估的，实测没有测出明确收益，仅作实验用 |
| `track_pops` | 关 | 所有国家的单个 pop 曲线 | 每游戏年约 +225 MB 内存，读档清零 |

**没有做的部分及原因**（预设的阈值：CPU 不能有可测量的下降；单项存档增量每年不超过约 0.5 MB、整局不超过约 10%；内存增加不超过约 200 MB）：
- **利益集团激进/忠诚只扩到 10 年。** 共 1744 条曲线，扩到 100 年需要 +72 MB 内存，到 100 年局末存档约 +54 MB（+18%），超过阈值。
- **州、建筑、单个 pop、政治运动、战争、市场价格不扩容。** 它们都不写入存档，读档即清零。其中政治运动和战争是按天采样，同样时长下内存是按周采样的 7 倍；建筑原版只给玩家国家记录。
- **不改"哪些曲线写入存档"。** 那需要改存档读写代码，风险是读档崩溃或存档损坏，不值得。

**扩容的生效时机**：容量在对象构造时确定，所以扩容补丁只对**之后读档或新开局**生成的对象生效。助手默认在游戏启动后约 1 秒内自动应用补丁，早于任何读档。

**安全措施**：
- 写入前挂起整个进程，检查所有线程的 RIP，确认没有线程停在被改的字节中间。
- 写入后刷新指令缓存并读回校验。
- 所有改动只涉及"仅供界面展示、不参与同步"的趋势数据。游戏代码里自带的说明是 "Trends must be used only for the visual presentation"。

## 四、性能实测（1943–1945 年存档，观察者模式，约 0.7 天/秒，游戏占用约 6 个 CPU 核）

- **`fix_pop_stats`**：开、关交替 8 轮，每轮 40 秒。
  - 关闭时 0.688±0.033 天/秒、9.79±0.79 CPU 秒/游戏日；开启时 0.745±0.025 天/秒、8.37±0.83 CPU 秒/游戏日。
  - 开启反而略好，但差异在 95% 置信区间内。CPU 秒/游戏日从第 1 轮的 10.9 降到第 8 轮的 7.3，存在随时间的漂移。结论：**测不出开销**。
- **扩容补丁**：只改变保留多久，不改变推送次数，所以 CPU 为 0；内存按第三节计算。
- **存档体积**：处理 1945 年存档（扩容 2808 条曲线、补回约 35 万个历史采样）后，309.0 MB 变为 310.5 MB（+0.5%）。
- 随时可以自测：在助手窗口点"性能测试 60s"，或运行 `python trend_keeper.py compare 60 fix_pop_stats`。

## 五、处理已有存档：`tools/恢复存档历史.bat`

双击后它会自动找到最新存档，以及同一局的所有旧存档（在 `save games` 和仓库根目录的 `history/` 中按 `playthrough_id` 匹配），然后依次执行：

1. **扩容**：容量与 `extend_saved` 一致。已经写满并循环覆盖的曲线，先按 `index % count` 还原成时间顺序。
2. **去除伪平线**：一个国家重新开始被记录时，游戏会用旧值把中间所有周填平，画出多年的水平线。真实人口几乎每周都在变，所以连续 52 周以上完全相同就判定为填充。
   - 如果之前有至少 1 年真实数据，填充段改成线性插值，并在报告中注明；
   - 否则曲线从第一个真实样本开始。
3. **补回被清空的历史**：用旧存档中的数据往前补。只有不超过 26 周（一个自动存档间隔）的空档才做线性插值，更长的空档不编造。

输出文件 `<存档名>_tk.v3` 会写到仓库根目录的 `restored/`，同时复制到 `save games`，以便游戏读取。原存档不会被修改。

## 六、使用方法

1. 在启动器的游戏合集里启用 **Trend Keeper - 历史曲线修复**（可选，只为了游戏内的按钮；补丁本身不依赖它）。
2. 双击桌面图标（第一次先运行 `python tools/trend_keeper.py shortcut`）。
3. 开关方式：助手窗口的开关；托盘右键菜单；快捷键 Ctrl+Alt+F9；CMF 侧边栏按钮；控制台 `effect tk_toggle = yes`、`tk_on`、`tk_off`、`tk_pop_stats_on`、`tk_track_pops_on` 等。
4. 窗口"补丁"页最上面的**当前存档**会显示补丁在这个存档里生效的游戏日期范围，例如 `1918.4.28 → 1918.7.17 · 2 个月`。游戏没有提供存档标识，所以以"游戏时钟连续的一段"为一个存档：时钟倒退或一下跳过 20 天以上视为读了另一个存档，落在以前某段范围内则视为同一个存档。记录从助手开始运行那天算起，之前的时间助手不知道。

命令行（在 `tools` 目录）：

| 命令 | 作用 |
|---|---|
| `status` | 附加到游戏，显示每个补丁的状态、游戏日期、内存 |
| `on [补丁名…]` / `off [补丁名…]` | 开关补丁，不写补丁名则操作全部默认补丁 |
| `selftest [exe路径]` | 离线检查 exe 是否适配，不需要开游戏；路径可用环境变量 `VIC3_EXE`，否则自动从运行中的游戏或 Steam 库里找 |
| `compare 60 补丁名` | 交替关/开/关各 60 秒，比较 CPU 和游戏速度 |
| `profile 30` | 只读热点采样：卡顿时线程在忙什么 |
| `invest [set 预算 最小 \| reset]` | 查看或在线修改 `cap_investment` 的参数和统计 |
| `coverage` | 列出每个存档段里补丁生效的游戏日期范围 |
| `shortcut` / `version` | 创建桌面快捷方式 / 显示版本 |

测试：`python -m unittest discover -s trend_keeper/tests -v`（需要 exe 的和需要 capstone 的测试在缺少时自动跳过）。

## 七、文件位置

- `tools/trend_keeper.py`：助手（窗口、托盘、命令行、补丁）；`tools/trend_restore.py`：存档历史恢复工具；`tools/trend_keeper.ico`：图标。
- `tools/trend_keeper_config.json`（开关和参数）、`tools/trend_keeper_coverage.json`（覆盖日期记录）、`tools/trend_keeper.log` 是本机生成的文件，已被 `.gitignore` 忽略。
- 恢复工具读取游戏 `save games` 里的存档，以及仓库根目录下的 `history/`（可选，放同一局的旧存档），输出到仓库根目录下的 `restored/`；可用环境变量 `TK_HISTORY_DIR`、`TK_OUT_DIR` 改位置。游戏读档必须从 `save games` 读，所以处理后的存档会在那里留一份副本，不用时可以删除。
- `common/`、`localization/`、`descriptor.mod` 是游戏内按钮 mod，放进 `Documents/Paradox Interactive/Victoria 3/mod/trend_keeper`（可用目录联接指向仓库）。
