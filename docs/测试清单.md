# 性能诊断清单(自主投资卡顿)

按顺序做,每一步都不需要重启游戏。上一步的结果决定下一步要不要做。

> 参考:作者在 1963 年存档上的第一次实测里,自主投资只占最忙线程的一部分,限制落地次数没有测出明确收益,详见 `autonomous_investment_perf_REA.md`。你的存档可能不同,按下面的步骤自己量。

## 0. 准备

- 启动 Trend Keeper(桌面图标或 `启动 Trend Keeper.bat`),进游戏读**卡顿的存档**,速度调到最快。
- 窗口里应显示"已附加 victoria3.exe"。若显示"只读"或"版本不符",停下来,日志在窗口的「运行日志」页和 `tools/trend_keeper.log`。

## 1. 先确认卡顿在不在自主投资(只读,安全)

在卡顿时点窗口里的"热点采样 30s",或运行:

```bash
python trend_keeper.py profile 30
```

看"含调用者的占比":

- "自主投资·串行落地"占比高(比如超过 20%)=> 推断成立,继续第 2 步。
- 占比很低 => 推断不成立,不要继续第 2 步。
- 同时看"在游戏代码里 / 在系统等待里"的比例,等待很多说明线程在等别的线程。

## 2. 量现状(不限制,只统计)

勾选"限制自主投资每周落地次数",把预算设成很大:

```bash
python trend_keeper.py invest set 100000000 1
```

玩 4~8 周后运行:

```bash
python trend_keeper.py invest
```

记下"最大潜在建筑数"和"原版最大落地次数"用它们校准预算。

## 3. 在线调参并对比

```bash
python trend_keeper.py invest set 20000 3
python trend_keeper.py compare 60 cap_investment
```

`compare` 会交替关、开、关各 60 秒,保持同一游戏速度、不要暂停。看三个数:

- CPU 秒/游戏日 的变化;
- 游戏速度的变化;
- 两次"关"之间的自身波动(变化比它小就不能下结论)。

预算越小限制越狠。可以多试几个值,每次 `invest set` 后重新 `compare`。

## 4. 体感与副作用

- 卡顿是否缓解。
- 私人建造是否明显变慢(看新建筑数量、建造队列有没有堆积)。
- 游戏有没有报错或崩溃。有的话保留 `logs/error.log` 和助手日志。

## 5. 随时可以退出

- 取消勾选"限制自主投资每周落地次数",立刻回到原版行为。
- 关掉助手或重启游戏,所有修改都消失。

## 对照实验(可选)

若第 1 步结果不明确,可以用 `perf_experiment/ai_invest_off` 把自主投资整个关掉,看卡顿是否消失。用法见该目录的 README.txt。测完记得取消勾选。

## 已知没验证的

- 补丁没有在运行的游戏上跑过。
- 热点采样器没有在真实游戏上跑过;栈扫描可能有少量误命中。
- 默认预算 20000、最小值 3 是估的。
- 多出的资金是否真的留到下周,是推断。
